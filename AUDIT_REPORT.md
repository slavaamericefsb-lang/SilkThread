# Аудит SilkThread — 15 ноября 2026

Проверка выполнена основным агентом и тремя субагентами: Core/откат, UI/асинхронность, обновления/установщик. Существовавшие рабочие изменения сохранены. Проверка исходного кода и регрессионные тесты не доказывают отсутствие всех ошибок на всех конфигурациях Windows.

## Подтверждённые исправления

* TweakEngine: ошибка проверки состояния после успешного применения больше не уничтожает данные отката; повторяющиеся ID в пакетах исключаются без учёта регистра.
* GameProfileService: учитываются false-результаты операций реестра; частичные ошибки не выдаются за успех; откат продолжает обработку после отдельной ошибки.
* GamesViewModel: объект игры фиксируется до await, смена выбора/фильтра не обновляет чужую игру; предотвращаются параллельные операции; при пустой выдаче сбрасывается выбор; ошибка Clipboard не показывает успех.
* ProgressBarAnimation: значение считывается до остановки предыдущей анимации; завершённые анимации освобождаются, конечное значение сохраняется; учитывается отключение анимаций Windows.
* UpdateService: ZIP проверяется на выход за каталог, абсолютные пути, ADS, ссылки и отсутствие файлов. Отмена после запуска обновлятора не оставляет DLL заблокированными вызывающим приложением.
* Скрипт обновления: исправлено ветвление errorlevel и обработка ошибок PowerShell; повторная ошибка распаковки запрещает запуск повреждённого приложения и удаление архива; исправлено экранирование путей.
* InstallEngine: пустой архив и небезопасный путь вызывают ошибку вместо ложного успеха.
* Тесты: старый тест игрового профиля заменён подменой операций реестра; добавлены воспроизводящие регрессионные сценарии.

## Ограничения на момент первого прохода (обновление ниже)

* Игровые профили не хранят исходные значения реестра: текущий откат удаляет параметры профиля, глобальные GameDVR-флаги не восстанавливает. Нужен отдельный механизм устойчивых снимков с учётом нескольких одновременно активных профилей.
* Обновление заменяет файлы на месте: остановка после ошибки предотвращает ложный успех, но не обеспечивает транзакционное восстановление уже заменённых файлов.
* AnimationSystemTests содержит проверки локальных констант, которые не подтверждают фактическое поведение WinUI. Полный визуальный и аппаратный аудит не выполнен.
* Системные твики, установка и обновление реальной системы специально через интерфейс не запускались. Основное окно до пересборки успешно открылось.

## Побочный эффект обнаруженного старого теста

Первый общий прогон выполнил существовавший Service_ApplyAndRevertProfile_ShouldExecuteWithoutCrashing. Он обращался к реальному реестру и упал на проверке успеха до отката. До прогона это не было замечено. Последующие прогоны используют изолированные операции.

Тест пытался установить следующие значения (часть HKLM могла быть отклонена правами):

* HKCU\Software\Microsoft\DirectX\UserGpuPreferences: cs2.exe = GpuPreference=2;
* HKCU\Software\Microsoft\Windows NT\CurrentVersion\AppCompatFlags\Layers: cs2.exe = ~ DISABLEDXMAXIMIZEDWINDOWEDMODE HIGHDPIAWARE
* HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\cs2.exe\PerfOptions: CpuPriorityClass=3, IoPriority=3
* HKCU\System\GameConfigStore: GameDVR_FSEBehaviorMode=2, GameDVR_HonorUserFSEBehaviorMode=1, GameDVR_DXGIHonorFSEWindowsCompatible=1

Исходные значения тест не сохранял. Автоматическое удаление не выполнялось, поскольку оно может уничтожить настройки, существовавшие до проверки.

## Второй проход: исправление оставшихся ошибок

* Игровые профили теперь сохраняют оригинальные значения до записи в атомарный JSON-журнал. Повторное применение не перезаписывает оригиналы. Есть восстановление после ошибки и повтор отката после перезапуска, учёт нескольких владельцев GameDVR, межпроцессная блокировка. Старые значения без снимка не удаляются вслепую.
* Обновлятор распаковывает патч отдельно, проверяет его и сохраняет оригинальные файлы и журнал до замены. Изолированный тест блокирует файл в тестовом каталоге: проверяются восстановление заменённых файлов и удаление новых при сбое. Журнал сохраняется при ошибке.
* RegistryOperations сохраняет MultiString, Binary/None и ExpandString без потери типа и подстановки переменных окружения. Повреждённые данные и недоступные снимки отклоняются до изменения реестра.
* TweakBuilder прекращает применение при недоступном снимке; многозначные операции захватывают все оригиналы до записей и пытаются восстановить их при ошибке. Откат больше не сообщает успех при отказе восстановления и не удаляет многозначную конфигурацию без снимка.
* Настройки сохраняются через временный файл и атомарную замену.
* Исправлены пустой экспорт Dashboard, двойные обработчики Scanner, выдуманные значения CPU cache/канальности RAM, обработка исключений Restore и сообщение rstrui. Escape не закрывает диалог во время применения пресета.
* Приложение ограничено одним экземпляром в пользовательской сессии.

### Оставшаяся область работ

Нельзя реконструировать настройки, которые прежние версии меняли без снимков. Падение питания во время обновления требует ручного восстановления по сохранённому журналу; автоматическое восстановление при аварийном завершении процесса не реализовано. Низкоуровневые P/E, HPET и MSI-X остаются явно обозначенным планом разработки. Полный визуальный/аппаратный обход всех конфигураций Windows не проводился. Это не подтверждение отсутствия всех возможных ошибок.
